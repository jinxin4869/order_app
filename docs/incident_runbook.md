# 注文障害の検知と代替受付・復旧の手順

注文の登録・取得・状態の更新ができなくなったときに、スタッフが気づき、営業を続けて復旧できるようにするための手順です。

## スタッフ向けの短い手順

1. **気づく**：スタッフ画面に赤い表示「注文の取得がN分以上止まっています」が出る、またはお客様から「注文できない」「結果がわからない」と言われる。
2. **確かめる（1分）**：端末の通信（Wi-Fi・モバイル回線）を確認し、スタッフ画面の「更新」を押す。別の端末でもスタッフ画面を開く。
3. **切り替える（3分以上直らないとき）**：
   - スタッフ画面が使えるなら、「メニュー管理」で「注文受付を停止する」。お客様の画面に停止の案内が出る。
   - 使えないなら、各テーブルに案内を置き、口頭でも伝える（下の「お客様への案内」）。
   - 紙の注文票で受ける（テーブル番号・品目・数量・受けた時刻・受けたスタッフ）。
4. **連絡する**：システム担当へ、始まった時刻と症状を伝える。
5. **戻す**：画面に「注文の取得が回復しました」が出たら、下の「復旧と照合」を行ってから、「注文受付を再開する」。

## 検知の対象と判定

| 対象                     | 判定                                                                                       | 知らせ方                                                                                                        | 担当             |
| ------------------------ | ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- | ---------------- |
| スタッフ画面の注文の取得 | 最後の成功から失敗が続いて60秒（15秒ごとの取得で4回）を超えた                              | スタッフ画面の上部に赤い表示（どのタブでも表示）。回復したら1回だけ回復の表示                                   | その場のスタッフ |
| 端末の通信               | 端末がオフライン                                                                           | スタッフ画面に「オフラインです」                                                                                | その場のスタッフ |
| お客様の注文の登録       | 送信の結果がわからない、または拒否された                                                   | お客様の画面の案内（[注文API契約](order_api.md)の「送信結果が不明な注文の復旧」）。お客様がスタッフに声をかける | その場のスタッフ |
| スタッフの認証           | ログインできない、権限を確認できない                                                       | スタッフ画面の表示                                                                                              | 店長 → 管理者    |
| 連投の制限               | 制限が発生した                                                                             | スタッフ画面の表示（[新規注文の連投制限](order_limits.md)）                                                     | 店長             |
| Functionsのエラー・遅延  | 例：`createOrder`のエラー率が5分間で5%を超える、`listStaffOrders`が5分間エラーを返し続ける | Cloud Monitoringのアラート（運用開始時に設定する）                                                              | システム担当     |
| 画面のエラー             | 例外                                                                                       | Sentry（`SENTRY_DSN`を設定した場合）                                                                            | システム担当     |

- スタッフ画面の表示は1か所だけに出し、失敗のたびに増やしません。回復の表示も1回だけで、「確認しました」で消えます。短い一時的な失敗（60秒未満）は、停止として知らせません。
- 通知やログに、秘密値・お客様の備考・注文の内容を含めないでください。Functionsのログは店舗IDとエラーの種類だけを出します。

### 運用開始時に決めること

| 項目           | 決める内容                                                                 |
| -------------- | -------------------------------------------------------------------------- |
| 現場の責任者   | 店長など。紙での受付への切り替えと再開を判断する人                         |
| システム担当   | Cloud Monitoring・Sentryの通知を受ける人と連絡先                           |
| 通知先の所有者 | 通知先のメールやチャットの管理者。担当が変わったら更新する                 |
| 確認の方法     | 運用開始時に、合成の障害（下の「試験」）で、表示と通知が届くことを確かめる |

## お客様への案内

注文の受付を一時的に止めたときに、テーブルに置く・口頭で伝える文です。

- 日本語：「ただいまスマートフォンからのご注文を一時停止しております。お手数ですが、スタッフにお声がけください。」
- English: "Ordering from your phone is temporarily unavailable. Please ask our staff to take your order."
- 中文：「目前暂停手机点餐。请联系店员点餐。」

## 復旧と照合

二重の調理と受付の漏れを防ぐため、受付を再開する前に照合します。

1. スタッフ画面の「すべて」で、止まっていた時間帯の注文を確認します。
2. 紙の注文票と、テーブル・時刻・品目で照合します。オンラインで受け付け済みの注文を、紙で二重に作らないでください。
3. お客様の画面が「結果を確認できません」だった注文は、受け付けていないと決めつけないでください。お客様の端末の案内（「前回の注文は受け付けられています」など）か、スタッフ画面の一覧で確認してから対応します。
4. 紙で受けた注文は、紙のまま調理・提供まで対応し、オンラインには入力し直しません（二重の調理を防ぐため）。紙の注文は日次の集計に含まれないので、運用の記録に件数を残します。
5. **再開の判定**：スタッフ画面が5分間続けて更新され、スタッフの端末から送ったテストの注文が一覧に届き、状態を更新できることを確かめます。確認できたら「注文受付を再開する」を押し、テストの注文はキャンセルします（理由「動作確認」）。

## 記録

障害ごとに、始まった時刻・気づいた方法・影響（止まった時間、紙で受けた件数）・対応・再開の時刻を、店舗の運用の記録（非公開）に残します。お客様の個人情報や注文の備考は書きません。

## 試験（合成）

本番の通知の設定や本番のデータを使わずに、次の方法で確かめられます。

- **画面の表示**：`npm run test`（`StaffScreen.test.js`）が、取得の失敗が60秒を超えると停止の表示が1つだけ出ること、タブを切り替えても見えること、回復で回復の表示に変わることを確かめています。
- **手で試す**：ローカルのデモ（[ローカルデモ投入](demo_setup.md)）でスタッフ画面を開き、エミュレーターを止める（または端末の通信を切る）→ 60秒後に停止の表示 → エミュレーターを戻す → 回復の表示、の順に確認します。
- **登録の失敗**：`npm run test:web`が、注文の応答が失われたあとの案内と、再読み込みのあとの復旧を確かめています。
