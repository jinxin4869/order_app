# 日次の集計

スタッフ画面の「集計」（`getDailyStats`）で、所属店舗の1営業日分の注文数・商品数量・人気の商品・提供までの時間を確認できます。会計連携の前なので、会計上の売上・利益ではなく、注文の実績と対応時間を表示します。

## 期間と日付の帰属

- 1回の表示で1営業日です。営業日は日本時間0時で切り替わります（[注文API契約](order_api.md)の「営業日と注文番号」）。
- 注文は、作成時に保存した`business_day`（注文した営業日）に数えます。0時をまたいで提供した注文も、注文した日に含めます。
- 「前日」「翌日」で日付を移動できます。今日より先には進めません。

## 指標の定義

| 指標         | 対象と分母                                                                                                                   |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| 受付         | その営業日に作成された注文の件数（キャンセルを含む）                                                                         |
| 注文         | 受付のうち、キャンセル以外の件数                                                                                             |
| キャンセル   | 状態がキャンセルの注文の件数（スタッフの全取消を含む）                                                                       |
| 訂正あり     | スタッフが減数・取消をした注文の件数（キャンセルを含む）                                                                     |
| 商品         | キャンセル以外の注文の商品数量の合計。訂正後の数量で数え、取り消した行（数量0）は数えません                                  |
| 人気の商品   | 商品ごとの数量（上と同じ数え方）の多い順に10件。同数なら、その商品を含む注文の件数が多い順                                   |
| 注文から提供 | 提供済み・対応完了の注文のうち、注文の作成時刻と提供の時刻（`served_at`）がある注文の、所要時間の中央値と平均（分、小数1桁） |
| 受付から提供 | 同じく、受付の時刻（`confirmed_at`）から提供の時刻まで                                                                       |

- 同じ`requestId`の再送は1件の注文として保存されるため、集計でも1件です。
- 提供の時刻は、スタッフが「提供済みにする」を押したときに記録します。記録を始める前の注文や、提供済みにせず対応完了にした注文には時刻がないため、推測で埋めずに「時刻の記録なし N件」として別に数えます。

## 上限と計算の方法

- 1営業日あたり最大2,000件の注文を読みます。超える場合は最初の2,000件だけを集計し、その旨を表示します。
- 集計は、画面を開いたとき・日付を移動したとき・「更新」を押したときに、その時点の注文のデータから計算します。保存済みの集計値はありません。あとから訂正や状態の変更があった場合も、開き直すと反映されます（再集計の操作は不要です）。
- 注文の作成や状態の更新の処理には影響しません（集計は別の読み取りです）。

## 閲覧の範囲

- 所属店舗のスタッフだけが、自店舗の集計を見られます。ほかの店舗の集計は取得できません。
- 返すのは件数・数量・時間と商品名だけです。注文の備考、テーブル、お客様やスタッフの情報は含めません。
- 対象外：スタッフ個人別の評価、全店舗の横断の分析、会計上の売上・利益。
