# 新規注文の連投制限

ログイン不要のQR注文を保ったまま、短時間の大量の注文による店舗の対応やシステムの負荷を抑えるため、新規注文の回数をサーバーで制限します。

## 対象と単位

| 単位     | 時間枠                                                 | 既定の上限 | 環境変数                |
| -------- | ------------------------------------------------------ | ---------- | ----------------------- |
| テーブル | 10分（固定の枠。日本時間の毎時0分・10分…で切り替わる） | 10件       | `ORDER_LIMIT_PER_TABLE` |
| 店舗全体 | 1分（毎分0秒で切り替わる）                             | 60件       | `ORDER_LIMIT_PER_STORE` |

- 数えるのは、新しく受け付けた注文だけです。同じ`requestId`の再送（応答が失われたあとの再試行など）は、保存済みの結果を返し、回数にも含めません。
- テーブルの上限は、着席したグループの通常の追加注文（10分に数回）に十分な余裕を持たせた値です。店舗全体の上限は、1秒に1件を超える受付が続く状況を異常とみなす値です。実際の来客数で記録を確認してから調整してください。
- 送信元のIPアドレスでは制限しません。同じ店舗のWi-Fiを使う複数のお客様を、まとめて止めてしまうためです。
- App Checkは正規のアプリからの呼び出しかを確かめるもので、回数の制限の代わりにはなりません。

## 判定

- 判定とカウントは、注文の保存と同じFirestoreのトランザクションで行います。同時に送られても、上限を超えて受け付けることはありません。
- 上限を超えた注文は`resource-exhausted`（`details.reason: "rate_limited"`、`details.scope: "table" | "store"`、`details.retryAfterSeconds`）で拒否します。注文・採番・テーブルの更新・カウンターは、どれも保存しません。
- お客様の画面は「短時間に多くの注文が送信されたため、受付を一時的に制限しています。約N分後にもう一度お試しいただくか、スタッフへお声がけください。注文は送信されていません。」と表示します（英語・中国語も）。カートはそのまま残ります。
- 解除は時間枠の切り替わりで自動的に行われます。手動で解除する操作はありません。

## 強制のスイッチ

`functions/.env`の`ENFORCE_ORDER_LIMITS=true`のときだけ拒否します。未設定や`false`の間は、上限を超えても注文を受け付け、超過を記録するだけです。

1. まず強制なしでデプロイし、営業中のスタッフ画面（下記）とログで、通常の営業で上限に達しないことを確認します。
2. 必要なら`ORDER_LIMIT_PER_TABLE`・`ORDER_LIMIT_PER_STORE`を調整します。
3. `ENFORCE_ORDER_LIMITS=true`にして、Functionsを再デプロイします。

戻すときは`ENFORCE_ORDER_LIMITS`を削除するか`false`にして、再デプロイします。

## 記録と対応

- カウンターは`restaurants/{restaurantId}/rate_limits/table_{tableId}`と`.../rate_limits/store`に1件ずつ持ち、時間枠が変わると上書きします。件数は増え続けません。
- 上限を超えるたびに、`restaurants/{restaurantId}/rate_limits/alerts`に、その時間（1時間単位）の回数・最後の単位・テーブル・時刻・強制の有無を記録します。注文の内容やお客様の情報は記録しません。
- これらはクライアントから読み書きできません（Firestoreルールで拒否）。スタッフ画面は、`listStaffOrders`の`limitAlert`で、その時間の記録だけを受け取ります。
- スタッフ画面の注文受付に「直近1時間に、短時間の連続注文の制限がN回ありました（最後：テーブル12）」と表示します。異常な注文が続く場合は、[メニュー管理](menu_management.md)で注文受付を停止し、受付済みの注文はそのまま対応します。
- Cloud Loggingにも、超過の単位と件数を警告として出します（注文の内容は含めません）。保持期間はCloud Loggingの設定に従います。
