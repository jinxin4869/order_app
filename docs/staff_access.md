# スタッフの認証・店舗権限

管理APIはFirebase Authenticationのログインと、管理者が付与したCustom Claimsを要求します。

```json
{ "role": "staff", "restaurantId": "restaurant-example" }
```

`restaurantId`は所属店舗のFirestoreドキュメントIDです。英数字・`_`・`-`の1〜128文字を使用します。
クライアントから渡されたロールや所属店舗を権限の根拠にしません。

- `updateOrderStatus`は対象注文の`restaurant_id`と所属店舗を照合します。
- `batchTranslateMenu`は対象メニューの店舗と所属店舗を照合します。
- 未ログインは`unauthenticated`、権限不足・他店舗操作は`permission-denied`を返します。
- お客様の注文作成はログイン不要ですが、Firestoreへの直接書き込みは禁止します。

Claimsの付与・変更は信頼できる管理者環境のAdmin SDKで行います。スタッフ本人にはClaimsを更新する権限を付与しません。
Claims変更後はIDトークンの更新が必要です。即時のアクセス停止が必要な場合は、アカウントの無効化とトークンの失効も行ってください。
認証情報や秘密鍵をリポジトリへ保存しないでください。

## スタッフ画面

`/staff`を開き、管理者が発行したメールアドレスとパスワードでログインします。Firebase Authenticationのメール／パスワードプロバイダーを有効にし、アカウント作成後に上記Claimsを付与してください。新規登録・パスワード発行はお客様用画面には設けません。ブラウザではタブのセッション内だけログイン状態を保持します。共用端末は利用終了時にログアウトしてください。

`listStaffOrders`と`getStaffOrder`はClaimsの店舗を根拠に取得します。クライアントのFirestore直接readは引き続き拒否します。対応中の注文は未受付・受付済み・調理中・提供待ち・提供済みです。「すべて」で完了・キャンセルも確認できます。最新50件を15秒ごとに取得し、新着件数を表示します。古い注文は「さらに前の注文を読み込む」で確認します。定期更新・手動更新は最新50件へ戻ります。端末のスリープやオフライン中は取得されないため、再開時に「更新」を押してください。

注文を選択すると料理・数量・要望と合計を確認できます。変更ボタンは許可された次の状態だけを表示し、確認後に実行します。`updateOrderStatus`は`expectedStatus`（画面で確認した状態）を必須とし、トランザクション内で比較します。競合は`aborted / status_changed`を返し、画面は詳細を再取得して再確認を求めます。自動で次の状態へ進めません。通信応答が失われた場合も再取得してから判断します。

「対応完了」は注文の作業終了を表し、決済済みという意味ではありません。POS・会計連携とテーブルの会計後の解放はこの画面の対象外です。

スタッフ画面を公開する前に、新しいFunctionsとFirestoreインデックスを反映してください。既存クライアントが`updateOrderStatus`を直接使っている場合は、`expectedStatus`を送る形へ同時に更新する必要があります。
