# メニュー管理（売り切れ・注文受付の停止）

スタッフは`/staff`の「メニュー管理」で、商品を売り切れ／販売再開にし、店舗の新規注文の受付を停止／再開できます。商品の公開・非公開、価格、名称、説明、画像、翻訳、店舗の`is_active`はこの画面では変更しません。

## 状態の分け方

| 項目                   | 場所     | 意味                                                                                                      |
| ---------------------- | -------- | --------------------------------------------------------------------------------------------------------- |
| `is_active`            | 店舗     | 管理上の利用可否。`false`ならQR・メニュー・注文をすべて止めます。メニュー管理では変更しません             |
| `ordering_enabled`     | 店舗     | 新規注文の一時的な受付可否。未設定は受付中、`false`は受付停止、それ以外の型は受付不可（設定の確認が必要） |
| `ordering_version`     | 店舗     | 受付状態の版番号。競合の検出に使います                                                                    |
| `is_published`         | 商品     | お客様への公開。`true`なら販売中・売り切れのどちらでもメニューに表示します。`false`は非公開               |
| `is_available`         | 商品     | 販売可否。`true`だけが販売中です。必ず真偽値で保存してください                                            |
| `availability_version` | 商品     | 販売状態の版番号                                                                                          |
| `is_available`         | カテゴリ | カテゴリの公開。`true`以外のカテゴリの商品は表示せず、注文もできません                                    |

| 商品の状態                                            | お客様のメニュー・詳細                     | お客様の操作                                       |
| ----------------------------------------------------- | ------------------------------------------ | -------------------------------------------------- |
| 販売中（公開・`is_available: true`）                  | 通常表示                                   | 追加・増数・注文できる                             |
| 売り切れ（公開・`is_available: false`）               | 「売り切れ」と表示して残す。詳細も見られる | 追加・増数・注文できない。カートからの削除はできる |
| 非公開（`is_published: false`、または非公開カテゴリ） | 返さない                                   | 注文できない                                       |

### 既存データ（`is_published`がない商品）

- `is_published`がない商品は、`is_available: true`なら公開、それ以外は非公開として扱います。これまで販売不可だった商品を、新しく「売り切れ」として見せることはありません。
- スタッフが初めて売り切れにした商品は、サーバーが同じ保存で`is_published: true`にします。メニューから消えずに「売り切れ」と表示されます。
- 販売不可の既存商品を「売り切れ」として見せたい場合は、管理者がAdmin SDKで`is_published: true`を設定します。非公開のままにする場合は`is_published: false`を設定します。分類が終わるまで、該当の商品はお客様に表示されません。

## スタッフの操作

- 公開中の商品だけを、カテゴリ・商品名・価格・状態とともに一覧にします。商品名の検索と、カテゴリ・販売状態での絞り込みができます。「公開中の商品N件のうちM件を表示」と表示します。
- 「売り切れにする」「販売を再開する」「注文受付を停止する」「注文受付を再開する」は、確認のあとで保存します。保存中は二重に操作できません。オフラインの間は操作できません。
- 保存は、画面で見ていた版番号（`expectedVersion`）と操作ID（`operationId`）を付けて送ります。
  - 別のスタッフが先に変更していた場合は`aborted`（`details.reason: "version_changed"`）になり、画面は最新の状態を取り直して知らせます。上書きはしません。
  - 応答が失われた場合も成功とは決めつけず、最新の状態を取り直して表示します。同じ操作IDの再送は、保存済みの結果を返します。
- 販売を再開しても、店舗の受付停止やカテゴリの非公開は解除されません。受付を再開しても、商品の売り切れは解除されません。日本時間0時になっても自動では再開しません。

### 操作の記録

変更と同じトランザクションで、`restaurants/{restaurantId}/menu_events/{operationId}`に、種類（`item_availability` / `ordering`）、対象の商品、変更前と変更後、スタッフのuidとメールアドレス、サーバーの時刻を残します。お客様やクライアントからは読み書きできません（Firestoreルールで拒否）。商品の文書にはスタッフの情報を書きません。

## お客様の画面

- メニュー・商品詳細・カートは、表示中に15秒ごと、画面に戻ったとき、通信が戻ったときに`getMenuAvailability`で販売・受付状態を確認します。前面にない画面は確認を止めます。
- `getMenuAvailability`は店舗の文書と、`is_available: false`の商品だけを読みます。商品の説明や翻訳は読み直しません。
- 受付停止中は、メニュー・商品詳細・カートに「現在、注文受付を一時停止しています。スタッフへお声がけください。」（英語・中国語も）を表示し、カートの「注文を確定する」を押せなくします。メニューの閲覧とカートの編集はできます。カートはそのまま残ります。
- カートの商品が売り切れになった場合は、その行に「売り切れのため注文できません。カートから削除してください。」と表示し、確定と増数を止めます。商品を勝手に削除したり置き換えたりはしません。
- 確認に失敗したときは「販売状況を確認できません。表示が最新ではない可能性があります。」と最終確認の時刻を表示し、「再確認」で取り直します。

## 注文時の判定

最終的な判定は`createOrder`がトランザクション内で行います。

| 状態                                         | 結果                                                                          |
| -------------------------------------------- | ----------------------------------------------------------------------------- |
| 受付停止中                                   | `failed-precondition`、`details.reason: "ordering_paused"`                    |
| 受付設定の型が不正                           | `failed-precondition`、`details.reason: "ordering_unconfigured"`              |
| 売り切れ・非公開・非公開カテゴリの商品を含む | `failed-precondition`、`details.reason: "item_unavailable"`、`details.itemId` |

- 売り切れの商品を含む注文は、全体を拒否します。販売中の商品だけを部分的に注文することはしません。カートは該当の行を示し、削除して改めて確定してもらいます。
- 停止や売り切れの変更より先に受け付けた注文は有効です。受け付け済みの同じ`requestId`の再送は、あとから停止・売り切れになっても元の注文結果を返します。

## API

| API                       | 権限               | 入力                                                              | 出力                                                                       |
| ------------------------- | ------------------ | ----------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `getStaffMenu`            | 所属店舗のスタッフ | なし                                                              | 店舗（名前・受付状態・版番号）、公開カテゴリ、公開商品（販売状態・版番号） |
| `setMenuItemAvailability` | 同上               | `itemId`、`available`（真偽値）、`expectedVersion`、`operationId` | `{ success, available, version }`                                          |
| `setOrderingAvailability` | 同上               | `enabled`（真偽値）、`expectedVersion`、`operationId`             | `{ success, ordering, version }`                                           |
| `getMenuAvailability`     | 不要               | `restaurantId`                                                    | `{ ordering: "open" \| "paused" \| "invalid", soldOut: [商品ID] }`         |

非公開の商品は、`getStaffMenu`・`setMenuItemAvailability`の対象外（`not-found`）です。Firestoreの`menu_items`の直接の読み取りも、公開中の商品だけに限ります。

## 運用

- 開店前に「メニュー管理」で受付中であること、前日の売り切れが残っていないことを確認します（売り切れは自動では解除されません）。
- 混雑や設備の不調で新規注文を受けられないときは「注文受付を停止する」を使います。受け付け済みの注文の確認と状態の更新は、停止中も続けられます。
- 対象外：商品の追加・削除、カテゴリの編集、公開・非公開の編集、在庫数の管理、自動の販売再開、予約の受付停止、会計・決済・POS連携。
